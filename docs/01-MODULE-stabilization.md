### 2026-10-03 - auth hardening pass (completes Module 0)

- **Schema/migration `20261003103521_add_sessions_mfa_audit_org`:**
  - New `Session` model (`jti` unique, `userId` FK cascade, denormalized `organizationId`, `expiresAt`, `revokedAt`, `ipAddress`, `userAgent`).
  - `User.mfaSecret String?` + `User.mfaEnabled Boolean @default(false)` + `User.sessions Session[]`.
  - `AuditLog.organizationId String?` + `Organization? @relation(onDelete: SetNull)` + index; `Organization.auditLogs AuditLog[]`.
- **Session revocation (fail-closed):** every JWT now carries a `jti`; `JwtStrategy.validate` looks up the session row and rejects missing/revoked/expired tokens with 401. `AuthService.logout` revokes the current session; `POST /auth/sessions/revoke-others` revokes all-but-current; `GET /auth/sessions` lists active sessions with `isCurrent`; `resetPassword` revokes every session for the account. Tokens issued before the Session table (no jti) are rejected - re-login required after a deploy (intended).
- **MFA (TOTP, `otpauth@9.5.2`):** `POST /auth/mfa/setup` mints a one-time base32 secret + `otpauth://` URL (shown once, not persisted); `POST /auth/mfa/enable` verifies a real code then persists `mfaSecret` + `mfaEnabled`; `POST /auth/mfa/disable` requires the current code; when MFA is on, `/auth/login` returns `{ mfaRequired, mfaToken }` (5-min JWT, **no cookie**) and `POST /auth/mfa/verify` checks the TOTP code (window 1) before issuing the session. Code lives in `AuthService.verifyMfa/verifyTotpCode` (uses `TOTP.validate({ token, window: 1 })` + `Secret.fromBase32` per this otpauth build's API).
- **Rate limiting:** new `security/guards/rate-limit.guard.ts` (in-memory sliding window, keyed by client IP + route, opportunistic bucket cleanup, 429 with `retryAfter`) registered as an APP_GUARD; activated only by the new `@RateLimit()` decorator (`common/decorators/rate-limit.decorator.ts`). Auth surface: login 10/5min, register 5/hr, forgot/reset 5/15min, mfa-verify 10/5min. Documented trade-off: per-process state - a multi-instance deploy needs a shared store (guard interface unchanged).
- **Audit tenant scoping:** `AuditInterceptor` now writes `organizationId` from the acting user; `AuthService` writes `organization` on LOGIN/MFA_ENABLED/MFA_DISABLED/PASSWORD_RESET. `AuditService.getAll` (new paginated list) + entity/user lookups accept an org filter; `AuditController` scopes ADMIN to their own org (cross-tenant audit reads 404) and gives SUPER_ADMIN the platform-wide view; `GET /audit` added.
- **Frontend:** login page handles the MFA step (6-digit code input after credentials); Settings gains a Security card (enable/disable 2FA with secret+code flow, active-sessions list, "revoke other sessions"); `authApi` extended (`verifyMfa`, `mfaSetup/Enable/Disable`, `listSessions`, `revokeOtherSessions`, `logout`); `AuthResponse` gained `mfaRequired?/mfaToken?/sessionId?`; `User.mfaEnabled?` added.
- **Tests (36 total, green):** `auth.service.spec.ts` (session issuance + jti linkage, MFA-disabled/enabled login paths, verifyMfa happy/bad-code/expired-challenge/no-MFA, enrollment setup/enable/disable, logout revocation, revoke-others, listSessions, reset-kills-sessions + expired token), `properties.service.spec.ts` (CRUD tenant-scoping pattern: create connects org, list filters org, read-by-id 404s cross-tenant, update/remove pre-verify ownership), `common/utils.spec.ts` (getTenantId fail-closed, isSuperAdmin, requireRecord, assertTenantRecord).
